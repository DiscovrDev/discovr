---
title: "pollDeviceCode()"
description: "Poll for auth token"
---

The second step of the device code flow. Call this repeatedly after showing the user code or QR code.

While the user hasn't confirmed yet, you'll get `&#123; status: "pending", interval &#125;` — wait `interval`
seconds and poll again. Once they approve, the response changes to `&#123; refreshToken, publicId, expiresAt &#125;`.
Store the `refreshToken` securely — it's your long-lived credential for all identity-tier calls.

**Polling interval:** the server sets it and repeats it in every pending answer; it grows the longer
the code has been waiting, so always use the latest value. The SDKs do this for you. Stop polling when
you receive a `refreshToken` or a `401` error.

A person can decline on their phone. Your next poll then returns `401` with `device-code-denied`
straight away (and on every poll after, until the code expires), so you can say so on screen instead
of waiting out the timeout.

## Parameters

| Name       | Type     | Required | Description                                                    |
| ---------- | -------- | -------- | -------------------------------------------------------------- |
| deviceCode | `string` | Yes      | The device code obtained from the request device code endpoint |

## Returns

`PollDeviceCode200Response` — Poll result. Two possible shapes:

- **Authorized**: device code was approved — contains `refreshToken`, `publicId`, `expiresAt`.
- **Pending**: user has not yet approved — contains `status: "pending"` and the `interval` to wait. Keep polling.
